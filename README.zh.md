## 这件作品证明什么

前三件作品都是"跑一次、出一个文件"。这一件要证明的是另一件事：**这套东西能自己跑，坏了会喊人。**

具体是：

- 多个来源写在配置文件里（`sources/feeds.json`），加来源不用改代码
- 每个来源失败会**重试**（指数退避），重试完还是失败才算失败
- 数据写进数据库，**重复跑不会重复插**（第二次跑全是 unchanged）
- **跨来源的重复记录不偷偷合并**：两行都保留，合并决定写进 `merges` 表，错了可以回退
- 每次运行都记账（`runs` / `feed_runs`：每个来源用了几次尝试、进来多少条）
- 出故障时写结构化告警 + **非零退出码**（0 正常 / 2 部分失败 / 3 全失败）——
  调度器就是靠这个码给人发通知的
- 每次运行生成一页状态报告（最近几次运行、各来源条数、重复数）
- 默认**离线演练**，不碰任何别人的服务器

## 怎么跑

```bash
python runner.py --offline                           # 用本地样例数据演练（默认）
python runner.py --online                            # 抓配置里的真实 URL
python runner.py --offline --inject-failure feed_b    # 演练"坏了会告警"
python verify_run.py                                  # 回读数据库，把每个数字重算一遍
```

只用 Python 标准库，不需要装任何第三方包；离线模式不需要联网。

## 实测结果（2026-10-16，Windows + Python 3.12）

| 跑法 | 结果 |
|---|---|
| 第一次 | `feeds_ok=3 seen=14 new=14 invalid=1 duplicates=2`，退出码 0 |
| 第二次（验证幂等） | `new=0 updated=0 unchanged=14`，退出码 0（一条都没重复） |
| 注入故障 | `status=partial feeds_ok=2/3`，写了告警，退出码 2 |
| 对账 | `all checks passed (12 checks)` |

## 关于"审计"

这件作品自带了 `audit.manifest.json`，意思是：它**必须**能通过 `_接单业务/audit/audit.py` 的审计才算交付物。
审计器会在一个临时副本里真跑一遍、注入故障、回读数据库对账，任何一项 FAIL 就不许交出去。
